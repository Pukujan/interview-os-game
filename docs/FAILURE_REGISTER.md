# Failure Register

Status: V0 preflight

| ID | Failure mode | Impact | Detection | Mitigation / containment | Residual risk |
|---|---|---|---|---|---|
| F-001 | Scope explosion into quiz + RAG platform + DSA runner + systems simulator + AI interviewer simultaneously | No playable product; infrastructure dominates learning value | Scope review, issue audit | `docs/SCOPE_BOUNDARY.md`; admission rule; general run bench deferred | Product owner may intentionally re-scope later |
| F-002 | Interview OS duplicates Study OS learner-state/mastery logic | Conflicting authorities and irreconcilable progress data | Architecture/schema review | Stable Study OS evidence-export boundary; game progression explicitly non-authoritative | Direct integration contract is not yet implemented |
| F-003 | Missions drift into trivia | High completion without interview reasoning/transfer | Content audit; changed-surface tests; user session review | Require capability intent and reasoning/diagnosis missions in V0 content mix | Some rapid-recall items are still useful and must not dominate |
| F-004 | LLM grading becomes arbitrary or authoritative | Learner receives misleading feedback | Replay fixtures; evaluator disagreement; schema validation | Explicit rubrics; deterministic evidence precedence; preserve derived status | Open-ended reasoning remains probabilistic |
| F-005 | Tooltip leaks solution | Inflated apparent unaided performance | Content review; leakage tests | Tooltip policy: definitions only; answer-direction belongs in hint ladder | Semantic leakage can be subtle |
| F-006 | Hint use is lost | Assisted success counted as unaided | Attempt-schema validation | Record assistance events + maximum assistance level | V0 UI must reliably emit events |
| F-007 | Practice/solution material contaminates transfer evaluation | False mastery/transfer evidence | Visibility-class audit; package scans | Separate practice and transfer identities; fail closed on declared hidden boundaries | Small personal corpus increases accidental familiarity risk |
| F-008 | Dataset or protocol drifts | Results cannot be reproduced | Result identity validation | Pin dataset/fixture/protocol/config identity | External sources can disappear; local curated fixtures may be needed |
| F-009 | Hidden labels ship in client | Evaluation becomes trivially inspectable | Build/package scan | Keep protected material server-side; only public-safe mission payloads bundled | Determined owner can inspect own backend; the goal is accidental leakage prevention, not adversarial DRM |
| F-010 | Visual/game layer increases cognitive load | Fun presentation makes learning slower or confusing | Phone usability sessions; task completion friction | Require visuals to communicate state/consequence/affordance; simplify when they do not | Aesthetic preferences are subjective |
| F-011 | Cross-platform visual performance is poor | Core game feel fails on one platform | Expo spike on iOS/Android-size targets | Validate one representative architecture diagram + animation before building broad UI | Device diversity remains after spike |
| F-012 | Backend outage blocks all study | Poor reliability for a personal learning tool | Failure-path test | Allow explicitly labeled local practice for client-safe missions; never fake server evaluation | Reasoning/dataset missions may remain unavailable offline |
| F-013 | LLM provider/model changes alter rubric judgments | Longitudinal scores become incomparable | Store evaluator/model/version identity; replay golden answers | Structured output contract; regression fixtures; avoid treating small score shifts as mastery change | Provider behavior can still drift |
| F-014 | Dataset-backed mission is too expensive/slow | Mobile session becomes tedious | Measured latency/cost on first adapter | Use bounded fixture/subset; cache immutable resources; keep run bench out of V0 | Realistic large-scale behavior is not simulated |
| F-015 | XP/streak incentives reward grinding over learning | User optimizes game metric rather than capability | Compare game state with capability evidence | No mastery claims from XP; favor transfer/unaided missions for important unlocks later | Any reward system can influence behavior |
| F-016 | Scraped/source-derived content has unclear provenance or wrong technical claims | Bad study material becomes canon | Source register + content review | Preserve source identity; authored mission review; deterministic/dataset checks where possible | Public sources themselves may contain mistakes |
| F-017 | First milestone over-engineers auth/cloud/persistence | Delays validation for no personal-user benefit | Issue/scope review | No public accounts/multiplayer; local game state acceptable; backend only where secrets/hidden eval require it | Later public use would require redesign |
| F-018 | Mission schemas change meaning without versioning | Old attempts become uninterpretable | Schema compatibility tests | Version mission/rubric/evidence schemas; fail unknown versions closed | Migration policy is deferred until first schema exists |
